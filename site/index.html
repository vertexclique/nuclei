Add it

One shard per core.

nuclei is a proactive IO runtime for Rust. Each shard runs its own tasks and drives its own IO, timers and buffers, and a task stays on the shard it was placed on. Every operation is completed for the task that asked for it: no task waits for readiness and then makes the call itself.

Add it

0.5.0 is not on crates.io yet: crates.io and docs.rs carry 0.4.3, the API before this rewrite. Until 0.5.0 is published, depend on its branch.

[dependencies.nuclei]
git = "https://github.com/vertexclique/nuclei"
branch = "modernize-2026"

Then a first program: an echo server, one task per connection.

use std::net::TcpListener;
use nuclei::Handle;

#[nuclei::main]
async fn main() -> std::io::Result<()> {
    let listener = Handle::<TcpListener>::bind("127.0.0.1:7000")?;
    loop {
        let (stream, _) = listener.accept().await?;
        nuclei::spawn(async move {
            let mut buf = [0u8; 1024];
            while let Ok(n @ 1..) = stream.recv(&mut buf).await {
                if stream.send(&buf[..n]).await.is_err() {
                    break;
                }
            }
        })
        .detach();
    }
}

It needs no configuration: the first spawn or block_on starts a runtime with one shard per core. A Builder sets every setting for a runtime of your own.

The runtime tries io_uring first and probes it safely, even under a seccomp filter that kills a process for calling io_uring_setup. CI runs the suite on io_uring and on epoll on Linux 6.1, 6.6 and 6.12, on kqueue on macOS, and on completion ports on Windows. NUCLEI_BACKEND picks one by hand.

What it has

Tasks
spawn, spawn_local for tasks that are not Send, spawn_blocking for blocking work, and block_on anywhere, nested in a task too, with the shard’s other tasks and IO still going.
IO
Handle<T> over std’s sockets, files and pipes, with the futures-io traits. Streams lend the driver your own buffer with read_owned and write_owned.
Time
sleep, timeout and intervals, on a timer wheel per shard.
Sync
Mutexes, reader-writer locks with upgradable reads, reentrant locks, semaphores, Notify, barriers, events, latches, once-cells, cancellation tokens, and mpsc, oneshot, broadcast and watch channels. They need only futures and wakers, so they work under any executor.
Processes
Children, their exits and their pipes; Unix signals and Windows console events as streams.
Stats
nuclei::stats(): every shard’s tasks, polls, IO in flight, buffers, timers and errors by kind.
Depends on
libc on Unix, the kovan crates, futures-io and futures-core. Nothing else.

Checked

  • TLA+ 27 families of models of the concurrent protocols: the task’s state machine, the park and wake handshake, an IO source’s sides and registrations, the ring’s operations, the sync primitives’ queues. Configurations that must pass sit beside mutations that must break them.
  • Lean Proofs of the arithmetic those protocols rest on: state words, counts, generations.
  • loom Models of the sync primitives and the runtime’s handshakes, run in CI.
  • ASan The suite under AddressSanitizer on both Linux backends, in CI.

proofs/README.md says what each model checks and what it leaves out.
