Chapter 11 of 12

Common errors

The messages you may meet, what each one means, and what to change. Each message is quoted as Nuclei prints it.

A spawned task never ran, or stopped halfway

No message at all: the Task was dropped, and dropping a task cancels it. A loop that spawns per connection and throws the handle away cancels every connection at once.

Fix: call .detach() on tasks nobody waits for, or keep the handles and await them. See Tasks.

the task has no output

Awaiting a Task whose runtime was dropped or shut down before the task completed panics with this message.

Fix: keep the runtime alive until its tasks are done, or await task.fallible(), which gives None in these cases instead of panicking.

names no backend of this platform

NUCLEI_BACKEND holds a name this system has no backend for. The message lists the names that work here.

Fix: set one of the names listed, or unset the variable.

asks for io_uring, but

io_uring was asked for by name (through NUCLEI_BACKEND, Builder::backend or NucleiConfig) and this process cannot have it. The reason follows but: here the crate was built without the iouring feature; on another machine it may be the kernel or a sandbox refusing the ring. A backend named by hand never falls back.

Fix: leave the backend unset, so auto picks io_uring where it can and the poller where it cannot; or turn the iouring feature back on; or run where io_uring is allowed (Linux 6.1 or later, and a sandbox that permits it).

the proactor is configured already

Proactor::with_config was called twice, or after the first IO, spawn or block_on, which configures the defaults.

Fix: call it once, first thing in main. With #[nuclei::main] the body already runs on the runtime, so use a plain fn main that configures and then calls nuclei::block_on, as in Production.

the default runtime is already running

Builder::build_global returned this error: a free function, the attribute or an earlier build_global started the default runtime first.

Fix: call build_global before anything spawns, or build a Runtime of your own and use its methods.

block_on is nested too deep

(Here the limit was set to 2; the default is 256.) Each nested block_on runs on the thread’s stack, and one level past the limit panics before the stack would overflow.

Fix: await instead of nesting where you can; raise Builder::max_nesting where you cannot.

block_on never returns

No message: a task called block_on on a future that waits for that very task. The task is not polled again until the call returns, so neither can finish.

Fix: wait for the other work with .await inside the task, not with block_on.

Data seems lost, or an error came late

Writes are accepted into the stream’s write-behind and sent by the driver, so a failed write can surface on a later write or on flush.

Fix: flush().await (or close().await) where you need to know the bytes reached the kernel. See Proactive IO.

A child’s wait fails with ECHILD

Something other than Nuclei reaped the child: the program ignores SIGCHLD, or calls waitpid itself.

Fix: leave SIGCHLD at its default and let Child::wait reap your children.
