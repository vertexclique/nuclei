Handles

Handle<T> takes one of std’s own IO types and gives it async operations. TCP, UDP, Unix sockets and files, one section each.

What a handle is

A Handle<T> owns a std IO object (a TcpListener, a UdpSocket, a File) and the source its shard’s driver reaches. The object stays std’s own type: Deref and get_ref hand it out for its own methods (addresses, socket options), and the handle’s async methods and trait impls do the IO. Handle::new(object) takes an object you made yourself; the constructors below make one for you.

Handle<TcpListener>bind, accept, incoming, accept_multi
Handle<TcpStream>connect, send, recv, peek, read_owned, write_ownedAsyncRead, AsyncWrite, also on &Handle

Handle<UnixDatagram>bind, pair, send, recv, peek, send_to, recv_from, peek_from
Handle<File>open, read_owned, write_ownedAsyncRead, AsyncWrite (also on &Handle), AsyncBufRead, AsyncSeek

bind, pair and new are plain functions; everything that waits for the network is async. The Unix types are on Unix only. On Windows a handle takes std’s TcpStream, TcpListener, UdpSocket and File, and a child process’s pipes.

TCP

bind makes a listener; port 0 asks the system for a free one. accept gives a connected Handle<TcpStream> and the peer’s address; connect dials out. send and recv move bytes; recv returning Ok(0) means the peer closed its side.

The futures-io traits

Streams implement AsyncRead and AsyncWrite, on the handle and on a shared reference to it, so one task can read and write the same stream, and any code written against those traits works with it: buffered readers, line splitting, copy. incoming() is a Stream of accepted connections.

accept_multi

accept_multi returns a stream of connections that owns its own copy of the listener, so it may outlive the handle. A connection reset before it was taken is skipped; any other error ends the stream, and take_error says what it was. On io_uring it keeps one accept armed for every connection that comes.

UDP

An unconnected socket sends with send_to and receives with recv_from, which also gives the sender’s address. connect fixes a peer; then send and recv talk to it alone. The peek forms read without taking the datagram.

Unix sockets

Unix only. A listener binds a path and accepts streams; pair makes two connected ends with no path at all. A UnixDatagram keeps message boundaries, like UDP.

Files

Handle::<File>::open(path).await opens a file for reading, as File::open does. For any other mode, open it with std’s OpenOptions and pass the file to Handle::new. Reads and writes share the handle’s cursor; seek moves it.

A regular file is always ready as far as a poller can tell, so on io_uring its reads and writes are ring operations at the cursor, and on the other backends they run as pread and pwrite jobs on the blocking pool; either way no shard waits. A File that is not a regular file (a FIFO, a terminal, a pipe) is a byte stream the driver serves like a socket.

Back to std

Through Deref every method of the std type works on the handle: local_addr, set_nodelay, set_ttl and the rest. get_mut, DerefMut and into_inner give mutable access or the object itself; before the object can change, the handle delivers the bytes it wrote behind, stops its other pending work and ends its registration, so the driver never touches a descriptor the handle no longer owns; the next operation registers the object again.
