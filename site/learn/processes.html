Chapter 8 of 12

Processes and signals

Child processes whose exits and pipes are async, and signals as streams.

In this chapter

  1. 08.01Running a program
  2. 08.02Talking to a child
  3. 08.03Ctrl-C
  4. 08.04Unix signals
  5. 08.05Windows console events

Running a program

nuclei::process::Command describes a process as std::process::Command does (arg, args, env, envs, env_remove, env_clear, current_dir, stdin, stdout, stderr), and as_std and as_std_mut reach the std command for anything it does not mirror. Three ways to run it:

  • output().await: pipes stdout and stderr (and gives the child an empty stdin unless you set one), collects both, and waits for the exit.
  • status().await: waits for the exit; the streams are inherited unless set.
  • spawn(): starts the child and returns a Child at once.

This example and the next run Unix programs (echo, true, sort).

Talking to a child

A spawned child’s piped streams are async: ChildStdin implements AsyncWrite, and ChildStdout and ChildStderr implement AsyncRead. Take them out of the Child with take(). Drop stdin (or close it) to end the child’s input.

  • wait().await waits for the exit without holding a thread; a piped stdin is closed first, so a child that reads it to the end can exit.
  • wait_with_output().await also collects the piped stdout and stderr.
  • try_wait() gives the status if the child has exited, without waiting.
  • kill() ends the child: SIGKILL on Unix, TerminateProcess on Windows.

A shard’s driver reports the exit and reaps the child: through a pidfd on epoll, EVFILT_PROC on kqueue, a wait on the process handle on Windows, and ring operations on io_uring. A wait fails with ECHILD if something else reaped the child first, for example when the program ignores SIGCHLD or calls waitpid itself.

Ctrl-C

nuclei::signal::ctrl_c().await completes when the process gets a Ctrl-C: SIGINT on Unix, the console’s CTRL_C_EVENT on Windows. Listening starts with the first poll, and from then on the default action of SIGINT (ending the process) is replaced for good.

Unix signals

nuclei::signal::unix::signal(kind) listens to one signal and returns a Signal, a stream whose every item stands for one delivery or more since the item before; recv().await takes the next. SignalKind names the usual ones (hangup, interrupt, terminate, quit, user_defined1, user_defined2, child, alarm, pipe, window_change) and SignalKind::from_raw takes any number (as_raw gives it back). poll_recv(cx) is the wait of recv for a hand-written poll.

signal fails for a number that is no signal, for SIGKILL and SIGSTOP (no handler can take them), and for SIGILL, SIGFPE and SIGSEGV (a handler for them cannot return).

Windows console events

On Windows, nuclei::signal::windows has ctrl_c, ctrl_break, ctrl_close, ctrl_logoff and ctrl_shutdown, each returning a CtrlEvent stream with recv. An event with a listener alive is taken; for close, logoff and shutdown the system ends the process once the handlers return, whatever they say.
