Every runtime setting

Every setting is optional; an unset one takes a default that needs no configuration to work well.

Builder methodDefaultWhat it sets
worker_threads(n)one per coreWorker threads, each running one shard. Zero runs every task on the thread that spawns it, while that thread is inside block_on.
max_worker_threads(n)four times worker_threadsThe most workers the runtime may start over its life; what spawn_more_threads may add up to.
pin_workers(bool)trueWhether each worker is pinned to its own core (Linux). A pinned shard keeps its cache warm.
thread_name(name), thread_name_fn(f)nuclei-worker, nuclei-blockingThe name of every thread the runtime starts.
thread_stack_size(bytes)8 MiBThe stack of every thread the runtime starts.
max_nesting(depth)256How deep block_on may nest on one thread.
max_blocking_threads(n)512The most threads the blocking pool runs at once.
thread_keep_alive(duration)10 secondsHow long an idle blocking thread waits for work before it exits.
local_spawn_margin(n)32How many more live tasks than another shard a spawning thread’s shard may hold and still take a task it spawns. Zero balances strictly.
io_buffer_cap(bytes)64 MiBThe most bytes each worker’s IO buffers hold; at the cap, IO waits for buffers to come back.
backend(IoBackend)the process’s choiceThe kernel interface this runtime’s workers use. One the process cannot have makes build fail with the reason. A non-empty NUCLEI_BACKEND overrides it.

build() starts the runtime; build_global() starts it as the process default (see Runtime).

The io_uring configuration

The io_uring ring of every shard is configured once per process, before any IO, with Proactor::with_config. A second call, or a call after IO has started (which configures the defaults), panics.

IoUringConfiguration fieldDefaultWhat it sets
queue_len2048Entries in the submission and completion queues.
recv_buffers256Buffers in each shard’s group for multishot receives: a power of two up to 32768. Zero turns multishot receives off; each read then takes a buffer of the shard’s own pool.
recv_buffer_size16384The size of each of those buffers, in bytes. For UDP, make it hold the largest datagram you expect.
sqpoll_wake_intervalNoneWith Some(ms), a kernel thread polls the submission queue and sleeps after that many idle milliseconds. More CPU, fewer system calls.
iopoll_enabledfalseBusy-waits for completions instead of interrupts. Only for files opened with O_DIRECT on file systems that support polling.
per_numa_bounded_worker_countSome(256)The kernel’s limit on io_uring worker threads per NUMA node for IO bound in time (regular files, block devices).
per_numa_unbounded_worker_countSome(512)The same limit for IO that may never complete, such as sockets.
aggressive_pollfalseKept for code written against earlier versions; the ring does not read it.

Four presets fill the struct from a queue length: interrupt_driven (no polling; the one to pick when unsure), low_latency_driven and kernel_poll_only (both with a kernel submission thread that sleeps after 2 idle milliseconds), and io_poll (with iopoll_enabled). NucleiConfig also carries backend, the backend of every runtime that names none.

Counters

nuclei::stats() takes a snapshot of every shard alive in the process (the workers of each runtime, then the shard of each thread that runs block_on) and of the blocking pools. It reads the shards without stopping them, so a running shard pays nothing for it. Most counts are published by a shard as it is about to wait for work, and by a busy shard at least once every few hundred task runs.

ShardStats fieldWhat it counts
worker, backendThe shard’s place among its runtime’s workers (None for a block_on thread’s shard) and its kernel interface.
tasks, polls, remote_wakesTasks on the shard not done yet; task polls run; tasks woken or spawned onto it from other threads.
ops_in_flight, cq_overflowsOperations handed to the kernel and not ended (io_uring, IOCP; always 0 on epoll and kqueue); times the kernel held completions for want of room in the completion queue (none is lost).
buffer_bytes, buffer_cap, buffer_exhaustedBytes the buffer pool holds; the most it may hold; times IO waited because every byte under the cap was in use.
timers, errorsTimers armed; IO errors by io::ErrorKind (get, iter), with refused registrations (refused_registrations) and accepts that found no descriptor left (accepts_out_of_descriptors) counted apart.

Stats also has blocking_threads and off_shard_errors, the errors of IO run on threads that run no shard.

A clean shutdown

A server stops taking connections when asked, lets the open ones finish, and gives up after a deadline. A CancellationToken carries the request to every task, ctrl_c raises it, and timeout bounds the drain.

The process default, the earlier way

Programs written against earlier versions of Nuclei set up the default runtime with init or init_with_config; both still work, on the shards. GlobalExecutorConfig sets the workers to start (with_min_threads, or from an environment variable with with_env_var), the most it may run (with_max_threads) and their names (with_thread_name_fn). spawn_more_threads and stop_thread grow and shrink it within those bounds.

Code that drove the proactor by hand still can. Proactor::get() is the process’s proactor and config its configuration; wait(max_event_size, duration) drives the calling thread’s shard once: its ready tasks, then its IO (for up to duration, or with None until some comes or wake is called), then the tasks that IO woke. wake ends every wait in progress.

Tests

#[nuclei::test] makes an async test: its body runs in block_on on the default runtime, or on a runtime of its own with threads = N. A test may return a Result, like any test.

#[nuclei::bench] makes an async benchmark for the nightly test harness: the crate that uses it writes #![feature(test)] and extern crate test; at its root, and each run of the body is timed on block_on.
