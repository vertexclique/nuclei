Chapter 2 of 12

Entry points and runtimes

Where async code starts: the attribute, a plain block_on, a runtime you build yourself, and handles that reach it from anywhere.

In this chapter

  2. 02.02block_on, without the attribute
  3. 02.03block_on nests

  5. 02.05Handles
  6. 02.06Configuring the default runtime

The attribute

#[nuclei::main] turns an async main into a program: its body runs in block_on on the default runtime. It may return anything main may, such as std::io::Result<()>. With threads = N the program builds a runtime of its own with N worker threads instead; threads = 0 runs every task on the thread inside block_on, with no worker at all.

block_on, without the attribute

nuclei::block_on runs a future to its end on the calling thread, running other tasks of that thread’s shard meanwhile. The first call (or the first spawn) starts the default runtime, so a plain fn main needs nothing else.

nuclei::drive does the same as block_on; it keeps the name earlier versions used.

block_on nests

block_on works anywhere, inside a task too. On a worker the call nests: the worker’s shard keeps running its other tasks, timers and IO until the future completes. That lets synchronous code deep in a call stack wait on a future without holding the shard up.

Two rules come with it. The task that called block_on is not polled again until the call returns, so a future that waits for that very task never completes. And each level runs on the thread’s stack, so the depth is bounded: 256 levels by default, set with Builder::max_nesting; one more panics with a message that says so.

A runtime of your own

Runtime::new() starts one with every setting at its default; Runtime::builder() (the same as Builder::new()) sets them. A runtime spawns, runs block_on and runs blocking work, like the free functions do on the default runtime.

Dropping a Runtime stops its workers, drops the tasks they still hold and waits for the threads to exit. shutdown_timeout bounds that wait: workers still running a task when it passes are left to exit on their own. Production lists every setting.

Handles

runtime.handle() gives a RuntimeHandle: cheap to clone, and usable from any thread to spawn on that runtime or to block_on. A handle does not keep its runtime running.

Configuring the default runtime

The free functions (spawn, block_on, spawn_blocking, spawn_local) use the runtime the calling thread is inside, or else the default runtime. To configure the default one, build it with Builder::build_global before anything starts it. RuntimeHandle::current() gives a handle to whichever runtime the thread is inside, or the default one, started on the spot if it is not running.

build_global fails with the default runtime is already running once a free function, the attribute or an earlier build_global has started it. Call it first thing in main.
