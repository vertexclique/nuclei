Futures and wakers, nothing else

Every wait in nuclei::sync is a future built from futures and wakers alone. A task that waits for a lock yields its shard instead of blocking the thread, and the same types work under any executor. Each primitive also has try_ forms that never wait, and blocking_ forms for plain threads. Called inside a Nuclei task, a blocking_ method runs a nested block_on, so the shard keeps running its other tasks.

Mutex, RwLock, Semaphore, Notify, Barrier, OnceCell, SetOnce and the mpsc, oneshot, broadcast and watch channels take the names, signatures, error types and documented behaviour of the established async sync API, so code written against that API compiles against these. Nuclei adds Event, Latch, Lazy, the upgradable read of the RwLock, reentrant locks keyed by an Owner, OnceCell::get_or_init_racy and CancellationToken.

Dropping a pending wait withdraws its waiter, and anything handed to it in the meantime is passed on, so no wakeup is lost. (A Barrier wait is the one exception: an arrival that was counted stays counted.)

Locks and semaphores let a caller take what is free even while others wait, so a release never waits for a sleeping task to run. Fairness is counted, not timed: a woken waiter that loses its retry MAX_BYPASS times (16) is owed a handoff, nobody gets in ahead of it, and the next release goes straight to it.

Locks

  • Mutex: lock().await, try_lock, blocking_lock, and lock_owned on an Arc<Mutex> (with try_lock_owned and blocking_lock_owned) for a guard that is 'static.
  • RwLock: read, write and upgradable_read, with owned and try_ forms; with_max_readers caps the readers.
  • ReentrantMutex and ReentrantRwLock: locks a holder may take again, keyed by an Owner token rather than a thread, because a task can move between threads and many tasks can share one. Owner::new() makes a token no other owner has had, and Owner::thread() gives the calling thread’s own (a ThreadOwner), for code on plain threads.
  • Guards: MutexGuard::map narrows a guard to a part of the locked value and try_map does it when the part may be missing; the read and write guards of the RwLock map the same way. RwLockWriteGuard::downgrade turns a write into a read in one step, so no writer gets in between.

Semaphores, notifications, events, latches, barriers

  • Semaphore: acquire and acquire_many give a permit that returns itself when dropped (acquire_owned and acquire_many_owned take an Arc<Semaphore> for one that is 'static), and a permit can split and merge. add_permits adds permits, forget_permits removes free ones for good, available_permits counts the free ones, and close makes every wait fail. A semaphore holds at most Semaphore::MAX_PERMITS.
  • Notify: notified().await waits; notify_one wakes one waiter (or the next one to come), notify_waiters wakes all that wait now, and notify_last wakes the newest waiter instead of the oldest. notified_owned waits through an Arc<Notify>.
  • Event: set once, wait forever after. Latch: opens when count_down brings its count to zero. Both have is_set, which looks without waiting.
  • Barrier: releases its waiters in groups of n; one waiter of each group is the leader.

Once-cells and lazy values

OnceCell::get_or_init runs an async initializer once while other callers wait for it; get_or_init_racy never waits: callers that race all build with a synchronous initializer, one value is published and the rest are dropped. SetOnce is set once, and readers can wait until it is. Lazy builds its value on first access (Lazy::force).

get_or_try_init takes an initializer that may fail: its error is returned, and the next caller runs its own. initialized says whether a cell holds a value. OnceCell::new_with(Some(value)) makes a cell that starts full, and const_new_with(value) does it in a static; SetOnce has the same two.

Channels

ChannelShapeNote
mpsc::channel(n)many senders, one receiver, at most n queueda send waits for room: backpressure
mpsc::unbounded_channel()many senders, one receiversend never waits and is a plain function
oneshot::channel()one value, one sender, one receiverthe receiver is the future; an error if the sender is dropped
broadcast::channel(n)many senders, many receiverskeeps the last n values, rounded up to a power of two; a receiver that falls behind gets Lagged
watch::channel(init)many senders, many receiverskeeps only the latest value; changed waits for one not seen yet

A channel closes once every sender is gone: the receiver takes what is left, then gets None (an error, for oneshot, broadcast and watch). What one sender sends comes out in the order it was sent.

Reserving room, batches and weak senders

A bounded sender can take its slot first and send later: reserve().await gives a Permit whose send cannot fail, reserve_owned moves the sender into an OwnedPermit, and reserve_many takes several slots. try_send and try_reserve never wait, and send_timeout waits at most a given time. recv_many takes what is queued, up to a limit, in one call. downgrade makes a WeakSender, which does not keep the channel open; its upgrade gives a sender back while another one lives.

A watch sender changes the value in place with send_modify, or with send_if_modified when the change may be nothing; send_replace returns the value it replaced, and a receiver’s wait_for waits for a value that passes a test. A broadcast receiver’s resubscribe makes another receiver, which takes the values sent from then on.

Cancellation tokens

A CancellationToken is a cancellation signal shared by many tasks, for a shutdown or for one job among many. A clone is the same token: cancelling one cancels all. A child_token is cancelled with its parent and can be cancelled alone, which never cancels the parent; a tree of tokens stops a whole part of a program at once. Like the rest of nuclei::sync, it needs no runtime.

Waiting is a future: cancelled().await completes once the token is cancelled, at once if it already is, and dropping it withdraws the wait and nothing else. A drop guard cancels its token when the guard goes, so a token can follow the life of a scope or a task:

Method of CancellationTokenWhat it does
fn new() -> CancellationTokenA token, not cancelled. Default makes the same.
fn cancel(&self)Cancels the token and every token derived from it, and wakes every task waiting on any of them.
fn is_cancelled(&self) -> boolWhether the token is cancelled: one atomic load.
fn child_token(&self) -> CancellationTokenA token cancelled with this one, which can also be cancelled alone. A child of a cancelled token starts cancelled.
fn cancelled(&self) -> WaitForCancellationFuture<'_>A future that completes once the token is cancelled, at once if it already is.
fn cancelled_owned(self) -> WaitForCancellationFutureOwnedThe same future, owning the token, so it can be spawned or stored.
async fn run_until_cancelled<F: Future>(&self, fut: F) -> Option<F::Output>Runs fut and gives its output, or None if the token is cancelled first (then fut is dropped). When both are ready together, the output wins.
async fn run_until_cancelled_owned<F: Future>(self, fut: F) -> Option<F::Output>The same, owning the token.
fn drop_guard(self) -> DropGuardA guard that cancels the token when it is dropped. disarm gives the token back and cancels nothing; token borrows it.
fn drop_guard_ref(&self) -> DropGuardRef<'_>The same guard over a borrowed token.

When cancel returns, the token and every descendant that existed when the call began are cancelled and their waiters woken, even where another call got there first. A child created at the same moment is cancelled by the time both calls have returned. The tree costs no memory past the tokens alive: a child leaves its parent’s registry when its last clone goes.

Lock-free maps and queues

nuclei::sync also holds the lock-free structures of the kovan crates the runtime is built on, so one module has every synchronization structure. None of them waits: they hold state that tasks and threads share, while a channel hands work over.

TypeWhat it is
HopscotchMapA concurrent hash map. Every method takes &self: insert, remove, get (a clone of the value), get_or_insert, compute (one atomic read-modify-write of a key), iter and keys.
SegQueueAn unbounded first-in first-out queue for many producers and many consumers. try_pop tells an empty queue (TryPopError::Empty) from one whose next value is still being written (Busy).
ArrayQueueA bounded queue with its capacity fixed by new; push hands the value back when it is full.
AtomOne value that readers load while a writer replaces it: load, store and swap are wait-free, and rcu applies a change, retrying only when another thread changed the value first.
