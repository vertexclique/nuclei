Tasks

Spawning work, waiting for its result, letting it run on its own or stopping it; tasks that are not Send, and work that blocks.

Spawn and await

nuclei::spawn takes a future that is Send + 'static and returns a Task<T>. A task is a future itself: awaiting it gives the task’s output. If the task’s future panics, awaiting the task resumes the panic.

Where a task runs

A task stays on the shard it was placed on: nothing steals it. Spawned on a worker, it stays on that worker unless the worker holds more live tasks than another shard by the runtime’s local_spawn_margin (32 by default). Spawned from any other thread, it goes to that thread’s home shard by the same rule; the first spawn takes the less loaded of two shards picked at random. So a task that waits for what it spawned keeps it on its own thread.

Dropping, detaching, cancelling

A Task owns its task. Dropping it cancels the task: its future is dropped without being polled again. To let a task run to its end with nobody waiting for it, call detach.

  • detach(): the task runs to its end; its output is dropped.
  • cancel().await: cancels the task and waits for its future to be dropped; gives back the output if the task had already completed.
  • fallible(): a handle whose await gives Option<T>, None where awaiting the Task would panic (the task was cancelled, or its runtime shut down before it completed).
  • is_finished(): whether the task completed or was cancelled; awaiting a finished task returns at once.

The most common surprise

A server loop that spawns a task per connection and drops the handle cancels each connection at once. Write nuclei::spawn(handler).detach(), as every server on these pages does.

Tasks that are not Send

nuclei::spawn_local takes a future that need not be Send and keeps it on the calling thread: the worker’s shard inside a task, or the thread’s own shard, where it runs while the thread is inside block_on.

Work that blocks

A blocking call (a synchronous file system walk, a CPU-heavy computation, a C library that waits) would hold its shard and every task on it. nuclei::spawn_blocking runs a closure on the runtime’s blocking pool instead and returns a Task for its result. The pool runs at most 512 threads at once by default, and an idle thread exits after 10 seconds; Builder::max_blocking_threads and Builder::thread_keep_alive change both.

More workers, or fewer

A runtime starts its workers when it is built and may start more later, up to Builder::max_worker_threads (four times the workers it started with by default). nuclei::spawn_more_threads(n).await starts up to n more and returns how many started. nuclei::stop_thread() stops one worker, unless only the minimum runs: it takes no new task from then on and exits once its tasks are done; stop_current_thread() stops the worker the calling task runs on. Both return a Task<bool> that says whether a worker was stopped. A stopped worker’s place is not taken again. Production shows them running.
