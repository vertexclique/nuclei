Which channel

ChannelFor
mpsc::channel(n)Many senders, one receiver, at most n messages waiting: a send waits for room, so a fast sender cannot run away.
mpsc::unbounded_channel()The same with no bound: a send never waits.
oneshot::channel()One value, once: a reply to a request.
broadcast::channel(n)Every receiver sees every message; one that falls n behind is told how many it missed.
watch::channel(v)One value many tasks read, and the news that it changed.
local::mpsc::channel(n), local::oneshot::channel()mpsc and oneshot for the tasks of one shard: not Send, with no atomic instruction on any path (Sync).
mesh::mesh(n, capacity)A bounded mpsc channel between every pair of n parties, such as one party per worker (below).

Like everything in nuclei::sync, they work under any executor, and their receives are safe to drop halfway. On a Nuclei shard a receive that completes spends one operation of the task's budget, so a loop on a channel that is never empty still lets the shard's other tasks run.

mpsc

Senders clone; the channel closes when the last one drops, and recv then gives None. recv_many takes up to a limit at once; the receiver's close stops new sends and lets it drain what is there.

Permits, timeouts, weak senders

reserve takes a slot before the value exists, so the send that uses the permit cannot fail; reserve_many takes several, reserve_owned one that moves. try_send never waits, and send_timeout gives up after a while and gives the value back. A weak sender does not keep the channel open.

oneshot

The sender can wait for the receiver to go away (closed), to stop work nobody will read.

broadcast

subscribe on the sender, and resubscribe on a receiver, add a receiver that takes what is sent from then on. A WeakSender sends only once upgraded, and does not keep the channel open.

watch

borrow reads the current value; changed waits for one this receiver has not seen, and wait_for for one that passes a test. send_modify changes the value in place, and send_if_modified tells the receivers only when the change says so.

A mesh between workers

mesh(n, capacity) joins n parties, each ordered pair by a bounded mpsc channel of capacity messages, and gives each its Party: its senders to every party and its receivers from every party, indexed by party. A party may send to itself, so a send to whoever owns a key needs no special case. The mesh only builds channels: put each party in a task of its own, here one per worker with spawn_on_worker.

  • send_to(to, value) waits for room on the channel to to alone: a full channel holds up no other pair. try_send_to never waits.
  • recv() takes from any party, with its index, round robin from the one after the last that delivered, so a party that floods cannot starve a quiet one. recv_from(from) takes from one party.
  • recv() ends once every channel into the party has ended. The party's sender to itself keeps one open, so a party calls close_senders when it is done sending.
  • n parties make n * n channels.

Cancellation tokens

A CancellationToken tells any number of tasks to stop. Clones share one state; a child token is cancelled with its parent, and on its own without touching the parent.

  • cancelled().await waits for it; is_cancelled() checks.
  • run_until_cancelled(future) gives Some(output), or None once the token is cancelled first, dropping the future.
  • drop_guard() cancels the token when the guard drops, however the scope ends.

A clean shutdown puts it to work.
