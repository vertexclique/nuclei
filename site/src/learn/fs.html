Whole files

nuclei::fs mirrors std::fs, with each call a future: read, read_to_string, write, copy, rename, remove_file, metadata, try_exists and the rest take a path and do the whole job.

Opening a file

A File is std's file in a Handle: File::open reads, File::create writes (creating or cutting the file), File::create_new fails if the file exists, and OpenOptions sets the rest (append, truncate, the mode and the open flags on Unix). A file reads and writes through the IO helpers and has a cursor that seek moves.

  • flush waits until the system has the bytes written behind; sync_all and sync_data put them on the device.
  • metadata, set_len, set_permissions, set_times and set_modified work on the open file; try_clone gives a second handle with a cursor of its own.

Lending buffers

As on streams (How it works), read_owned and write_owned take your vector and give it back, so no byte is copied.

Directories

create_dir, create_dir_all and DirBuilder (recursive, with a mode on Unix) make them; remove_dir and remove_dir_all take them away. read_dir streams the entries a page at a time, so a directory of any size is read without holding it all.

Links: hard_link, read_link and canonicalize, symlink on Unix, symlink_file and symlink_dir on Windows.

Where file IO runs

A regular file is always ready to the kernel, so no poller can say when its IO would wait. On io_uring a file's reads and writes go to the shard's ring; on the other backends each is a job of the blocking pool, at the handle's own cursor. Calls by path, and the calls beside a file's reads and writes, run on the blocking pool. A File that is not a regular file (a FIFO, a terminal, a pipe) is a byte stream the driver serves like a socket.
