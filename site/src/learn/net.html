TCP

nuclei::net has the socket types: TcpListener, TcpStream, UdpSocket and, on Unix, UnixListener, UnixStream and UnixDatagram. Each is std's own socket in a Handle: the handle adds the async calls, and std's methods (local_addr, peer_addr, set_ttl, ...) work through it.

  • bind and connect are async, since a name may need looking up. Each takes the first address that works.
  • recv and send work on a shared reference; the stream is also AsyncRead and AsyncWrite, on the handle and on & the handle, so one task can read while another writes.
  • incoming() gives the connections as a stream. accept_multi() gives a stream that owns a copy of the listener, so it may outlive the handle; on io_uring one accept stays armed for every connection that comes.
  • An accept skips a connection its peer reset while it waited in the backlog, and takes the next one: the error (ECONNABORTED, on Windows WSAECONNRESET or ERROR_NETNAME_DELETED) is that connection's, not the listener's. Linux hands such a connection over as it is, and its first read reports the reset. The listener's own errors, such as running out of descriptors, still come back from accept and end accept_multi's stream.
  • read_owned and write_owned lend the driver a buffer of yours, and read_vectored_owned and write_vectored_owned lend several in one call (IO utilities).

Addresses and names

Every call that takes an address takes anything ToSocketAddrs accepts: a SocketAddr, an (ip, port) pair, a "host:port" string, a (host, port) pair, or a slice of addresses. Numbers are used at once; a name is looked up on the blocking pool, so no shard waits on the resolver. net::lookup_host looks one up alone.

UDP

A bound socket sends datagrams to any address and receives them with their sender's; a connected one talks to one peer. A datagram larger than the buffer is cut to fit.

peek and peek_from look at the next datagram without taking it, peek_sender names its sender without copying a byte, and recv_buf and recv_buf_from receive into a ReadBuf that need not be initialized.

Unix sockets

Streams and datagrams over a path in the file system, or a connected pair. A stream knows its peer: peer_cred gives the user and group, and the process where the system tells it (Linux, Android, macOS, iOS).

A connect to a listener whose backlog is full waits until the listener takes it, as std's blocking connect does. Linux answers such a connect at once, so the connect tries again on its own socket after a pause on a timer (1 ms, doubled up to 64 ms). No thread waits for it, the options set on the socket stay, and dropping the future frees everything.

On Linux a socket may also take a name in the abstract namespace, with no file behind it: bind_addr and connect_addr take std's SocketAddr, made with from_abstract_name.

Socket options

A socket to set up before it listens or connects is a TcpSocket: buffer sizes, address and port reuse, keepalive, TCP_NODELAY, linger, the type of service or traffic class, IPV6_V6ONLY, and on Linux the network interface (bind_device). Then listen or connect turns it into a listener or a stream. A stream that is connected already sets linger and no-delay on the handle. The TCP options below go further.

UnixSocket is the same for Unix sockets: new_stream or new_datagram, bind, then listen, connect or datagram.

TCP options

A TcpKeepalive times the keepalive probes: time idle before the first, interval between them, and retries unanswered before the connection drops. A field left None keeps the system's value; times are whole seconds. set_keepalive_timing turns the probes on with that timing, on a TcpSocket or on a connected stream, and keepalive_timing reads it back.

A connected TCP stream also has set_keepalive_timing and set_user_timeout. Each option has its getter (user_timeout, incoming_cpu, fastopen, ...). An option the system does not have answers Unsupported, so code for several systems can try it and go on.

A UDP socket set up first

Some options only a socket that is not bound yet takes. UdpSocketBuilder is that socket: new_v4 or new_v6, then address and port reuse, buffer sizes, the type of service (IP_TOS) or the traffic class (IPV6_TCLASS), set_only_v6, and on Linux the network interface (bind_device). bind turns it into a UdpSocket.

Two halves

A TCP or Unix stream splits into a read half and a write half: split() borrows the stream and allocates nothing; into_split() gives owned halves that move into tasks of their own, and reunite puts them back together.

Ending a stream

A stream ends in one of three ways, each telling the peer something different:

  • shutdown().await, from AsyncWriteExt, flushes and ends the write side: the peer reads every byte, then the end.
  • shut(how), on a TCP or Unix stream, is std's shutdown made once the bytes written behind reached the kernel. Shutdown::Write and Both wait for those bytes, so the peer reads them all before the end; Read leaves the writes alone. Where the calling thread's shard runs io_uring, the reading half is shut through the ring.
  • abort() closes a TCP stream now: SO_LINGER goes to zero, the bytes written behind are dropped, and the peer's reads fail with ConnectionReset.

After shut(Read) or shut(Both), reads answer as std's do on each system: Linux hands out what came before, then the end; macOS and Windows end at once, so there the handle drops what it read ahead too. The call is not named shutdown, so stream.shutdown(how) still reaches std's own through the handle, which shuts the halves at once: bytes still behind then never reach the peer.

A stream that is only dropped still delivers its bytes behind and ends cleanly. One whose time for that runs out resets the connection, as abort does (How it works).

Files and large writes

send_file(&file, offset, len) sends a range of a file to a TCP or Unix stream. Where the system has sendfile(2) or TransmitFile, the bytes go from the page cache to the socket inside the kernel; elsewhere they are read and written, which works the same. Each call runs on the blocking pool and sends at most send_file_chunk bytes (1 MiB by default), so a cold page holds a pool thread for one chunk at most.

write_zero_copy writes a lent buffer as write_owned does, and asks the kernel not to copy it either. The write ends once the kernel took the last byte; the buffer comes back through a Released once the peer acknowledged every byte. Only io_uring sends zero-copy, on the runtime's workers, and only while the write has at least zero_copy_threshold bytes left (1 MiB by default). Below it, and on the other backends, the kernel copies and the Released is ready at once.

Pipes and FIFOs

net::unix::pipe::pipe() makes an anonymous pipe: a Sender and a Receiver, async streams like any other. A named pipe in the file system opens with pipe::OpenOptions, as a receiver or a sender.

std's calls through the handle

std's methods reach the socket through the handle, and the handle's own methods of the same name take their place where it has them (connect, send, linger, ...). A few of std's go around the bytes the handle read ahead and wrote behind, or block its shard:

  • shutdown(how) shuts the halves at once, ahead of the bytes still behind; shut waits for them.
  • set_nonblocking(false) makes the driver's own calls on the socket block the shard's thread, and every task of the shard with them. A socket nuclei takes over is non-blocking on Windows too, as on unix.
  • take_error takes the socket's pending error, which the handle's connect in progress or its next operation would have answered.
  • std's Read and Write on a shared reference to the socket read past the bytes read ahead, write ahead of the bytes written behind, and answer WouldBlock where the handle's own calls wait.
  • UdpSocket::connect(addr) makes a new connected socket. socket.connect(addr) on a socket you have is std's: it connects that socket in place and looks a name up with a blocking call on the shard's thread, so give it a numeric address, or look the name up first with net::lookup_host.

The Handle reference has the details.
