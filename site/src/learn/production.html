Every runtime setting

Every setting is optional, and an unset one takes a default that needs no configuration to work well. Set them on a Builder, then build a runtime of your own or build_global the default one (Runtime).

Hooks

A runtime calls hooks of yours on its threads and around its tasks: for metrics, tracing or thread setup. Each task hook is given the task's Id.

A hook runs in the middle of the runtime's work: keep it short, and never panic in one.

The io_uring configuration

The ring of every shard is configured once per process, before any IO, with Proactor::with_config. A second call, or one after IO has started (which configures the defaults), panics.

Four presets fill the struct from a queue length: interrupt_driven (the one to pick when unsure), low_latency_driven and kernel_poll_only (a kernel submission thread), and io_poll. NucleiConfig::backend is the backend of every runtime that names none.

Counters

nuclei::stats() takes a snapshot of every shard alive in the process (each runtime's workers, then the shard of each thread in block_on) and of the blocking pools. It reads the shards without stopping them; most counts are published by a shard as it is about to wait for work, and by a busy one every few hundred task runs.

Stats also has blocking_threads, and off_shard_errors for IO run on threads that run no shard.

A clean shutdown

A server stops taking connections when asked, lets the open ones finish, and gives up after a deadline. A CancellationToken carries the request to every task, Ctrl-C raises it, a JoinSet holds the connections, and timeout bounds the drain.

Tests

#[nuclei::test] makes an async test: its body runs in block_on on the default runtime, or on a runtime of its own with threads = N or start_paused = true (paused time). A test may return a Result, like any test.

#[nuclei::bench] does the same for a benchmark on the nightly test harness.

The earlier entry points

Programs written against earlier versions set up the default runtime with init or init_with_config; both still work, on the shards. GlobalExecutorConfig sets the workers to start (with_min_threads, or from an environment variable with with_env_var), the most to run (with_max_threads) and their names. spawn_more_threads starts more workers, up to the maximum, and stop_thread drains one: it takes no new task and exits once its tasks are done.

Code that drove the proactor by hand still can: Proactor::get().wait(max_events, timeout) drives the calling thread's shard once, and wake ends every wait in progress.
