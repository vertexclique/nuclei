Futures and wakers, nothing else

Every wait in nuclei::sync is a future built from futures and wakers alone, so it works under any executor, not only Nuclei's. A contended wait queues and returns Pending; it never blocks a thread.

  • Familiar names. Mutex, RwLock, Semaphore, Notify, Barrier, OnceCell and SetOnce keep the names, signatures and errors of the established async sync API: code written against it compiles after a change of import.
  • Every wait has a try_ form that never waits, and a blocking_ form for threads that may block. On a Nuclei shard a blocking_ call nests a block_on, so the shard keeps running its other tasks.
  • Dropping a wait loses nothing. A dropped future withdraws its place in line and passes on what was handed to it, so no wakeup is lost. A Barrier wait is the one exception: an arrival that was counted stays counted.
  • Fair to the shard. On a Nuclei shard, a lock, an acquire or a receive that completes spends the task's budget, so a loop on one that is always ready still lets other tasks run. Under another executor there is no budget.

Mutex

Uncontended, taking and releasing the lock is one atomic operation each. It does not poison: a panic in a holder unlocks it. lock_owned holds the lock through an Arc, so the guard can move into a task; MutexGuard::map narrows a guard to a part of the value.

RwLock

Readers share the lock, a writer has it alone. An upgradable read sits beside plain readers (one at a time) and turns into a write without letting another writer in between: read, decide, then write.

A write guard downgrades to a read guard, and with_max_readers bounds how many readers share it.

Reentrant locks

ReentrantMutex and ReentrantRwLock may be taken again by the holder that has them. The holder is an Owner token, not a thread: a task can move between threads, and many tasks can share one.

Semaphore

A semaphore hands out permits; a permit goes back when it drops. It bounds how many tasks do something at once.

acquire_many takes several at once, forget keeps a permit from going back, add_permits adds more, and close makes every wait fail.

Once-cells and lazy values

OnceCell holds a value set once; get_or_init runs an async initializer, and callers that come meanwhile wait for it. SetOnce is set from anywhere, and wait waits until someone has. Lazy computes its value on first use.

Fast, and fair by count

The locks and the semaphore let a caller take what is free even while others wait, so a release never waits for a sleeping task to run. A waiter that loses MAX_BYPASS times is owed a handoff: nobody gets in ahead of it, and the next release goes to it directly. Fairness is counted, never timed.

The task's budget

On a Nuclei shard, a lock or a semaphore acquire that completes spends one operation of the task's budget, as IO does, and so do a channel receive that completes and a bounded send that completes at its first try. Once the budget is spent the call completes nothing: it wakes its task and answers Pending, so the task goes behind the shard's other tasks.

  • A wait that queued and was then granted spends nothing, so it keeps what it waited for.
  • The try_ forms never spend. Notify, Event, Latch, Barrier and the once-cells keep no budget.
  • Off a Nuclei shard, under another executor, there is no budget, and these calls never yield for it.
  • coop::unconstrained runs a future with no budget, and budget_yields counts how often a shard's tasks yielded for it.

For the tasks of one shard

nuclei::sync::local has twins of mpsc, oneshot, Semaphore and Mutex for tasks that share one thread: spawn_local tasks, and the future block_on runs. Their state sits in an Rc and plain cells, so no path makes an atomic instruction or a fence, and a message between two tasks takes fewer instructions than on the shared channel (CI counts both, in the mpsc and local_mpsc rows of ci/op_budget.txt).

  • Not Send. The types are neither Send nor Sync, so the compiler keeps them on the thread that made them. Share one between tasks with an Rc.
  • The same names and errors. Code switches by changing the path. Left out are the blocking_ forms, which on one thread could only wait for themselves, and the weak sender.
  • First come, first served. Waiting sends, acquires and locks are served strictly in the order they came, and a try_ form fails while anyone waits. The shared locks let a caller in ahead of a waiter (fair by count); these never do.
  • Dropping a wait loses nothing, and the budget applies as it does to the shared ones.

Lock-free maps and queues

For state shared across threads without a lock at all:

  • HopscotchMap: a concurrent hash map; values are cloned out.
  • SegQueue: an unbounded queue. ArrayQueue: a bounded one whose push refuses when full.
  • Atom: a value read without a lock and replaced whole.
